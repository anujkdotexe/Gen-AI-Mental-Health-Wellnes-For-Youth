# Contributing to MindSpark AI

Thank you for your interest in contributing to MindSpark AI! This project aims to provide accessible mental health support for youth through AI technology, and we welcome contributions from developers, mental health professionals, and advocates.

## 🌟 How to Contribute

### Types of Contributions
- **Code**: Frontend/backend development, bug fixes, new features
- **Documentation**: Improve README, add code comments, write guides
- **Testing**: Write tests, report bugs, improve test coverage
- **Design**: UI/UX improvements, accessibility enhancements
- **Mental Health Expertise**: Review AI responses, improve crisis detection
- **Translation**: Localization for different languages

## 🚀 Getting Started

### 1. Fork and Clone
```bash
git clone https://github.com/yourusername/Gen-AI-Mental-Health-Wellnes-For-Youth.git
cd Gen-AI-Mental-Health-Wellnes-For-Youth
```

### 2. Set Up Development Environment
Follow the setup instructions in the [README.md](README.md) to get both frontend and backend running locally.

### 3. Create a Feature Branch
```bash
git checkout -b feature/your-feature-name
```

## 📝 Development Guidelines

### Code Style
- **Frontend**: Use ESLint and Prettier configurations
- **Backend**: Follow PEP 8 Python style guide
- **Commits**: Use conventional commit messages
- **Documentation**: Comment complex logic and mental health-related code

### Mental Health Considerations
- **Sensitivity**: All AI responses must be reviewed for appropriateness
- **Crisis Handling**: Test crisis detection thoroughly
- **Privacy**: Never log or store sensitive user data
- **Professional Boundaries**: Clearly indicate when professional help is needed

### Testing Requirements
- Write unit tests for new features
- Test edge cases, especially for mental health scenarios
- Include integration tests for API endpoints
- Test accessibility features

## 🔄 Pull Request Process

### Before Submitting
1. **Run Tests**: Ensure all tests pass
   ```bash
   # Frontend
   cd frontend && npm test
   
   # Backend
   cd backend && pytest
   ```

2. **Check Code Quality**
   ```bash
   # Frontend linting
   npm run lint
   
   # Backend formatting
   black . && flake8
   ```

3. **Update Documentation**: Update README if needed

### PR Template
When submitting a pull request, include:
- **Description**: What does this PR accomplish?
- **Mental Health Impact**: How does this affect user experience?
- **Testing**: What tests were added/modified?
- **Screenshots**: For UI changes
- **Breaking Changes**: List any breaking changes

## 🐛 Bug Reports

When reporting bugs, include:
- **Environment**: OS, browser, Python/Node versions
- **Steps to Reproduce**: Clear, step-by-step instructions
- **Expected vs Actual**: What should happen vs what happens
- **Screenshots/Logs**: Visual evidence or error logs
- **Mental Health Context**: If related to crisis features or sensitive content

## 💡 Feature Requests

For new features:
- **Use Case**: Describe the mental health need this addresses
- **User Story**: "As a [user type], I want [goal] so that [benefit]"
- **Mental Health Research**: Include relevant research or best practices
- **Privacy Considerations**: How will this maintain user privacy?

## 🔒 Security and Privacy

- **Never commit secrets**: Use environment variables
- **Data Protection**: Follow GDPR and HIPAA principles
- **Vulnerability Reports**: Email security issues privately
- **User Data**: Minimize collection, maximize protection
